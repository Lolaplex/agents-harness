# AGENTS.md — agents-harness Developer Guidelines

## Architecture Principles
- **Per-request loop**: The agent is a reconstructed trace (`python -m runner.loop`). SKILL/MCP/A2A entries live in `runner/modules/` as Cordis verbs (`when=on_request` or `later`). Scheduled care jobs stay in `runner/schedules/`. plexd is not on this path.
- **Session gate (`runner/session_gate.py`)**: The first HOST-LOCAL tool call in a loop process binds the session to this host — the gate fires `AGENTS_SESSION_BIND_CMD` once per process (`{session}`/`{tool}`/`{workspace}` placeholders) and the host app maps that to a `session:host` record. Host-local = canonical names in `HOST_LOCAL_TOOLS` (git, mcp.terminal, mcp.browser, mcp.delegate, mcp.fs, mcp.proc/process, mcp.voice, mcp.keys, mcp.attest, fs, proc, terminal, workdir, repo.pre_pr, vision.analyze), a manifest flagged `host_local: true`, or a stdio `mcp_remote` server. ws-data tools (memory/calendar/traces/persona/schedule/skills) and HTTP/SSE remotes stay portable. The checked name is always the canonical `mod["name"]`, never the raw LLM tool string. The gate runs after approval, before the tool executes, and fails closed: `SessionGateError` aborts the call instead of running unbound. `AGENTS_PARENT_SESSION` makes delegate/persona children bind the root session.
- **Workspace reads**: `runner/workspace_config.py` reads host `agents.json` + `<ws>/config.json` without creating a workspace; `runner/workspace_tree.py` resolves the workdir and does the shallow repo scan (VCS/dependency/cache dirs skipped).
- **MCP like the other agents-* packages**: `mcp.json.example` plus `python -m runner.mcp_server` is the server. External servers are a client: `<host>/mcp.json` (`AGENTS_MCP_CONFIG_FILE`, alias `AGENTS_MCP_CONFIG`; optional `<host>/mcp/ws-<id>.json` and untrusted `<ws>/mcp.json`), catalog modules `mcp.<server>.<tool>` with kind `mcp_remote`. Optional extra `pip install -e ".[mcp]"` (FastMCP server and the client SDK). The executor stays stdlib. Each loop turn is a new process: the resolved module catalog is snapshot-cached under `<host>/cache/catalog-cache[-<ws>].json` (`AGENTS_CATALOG_CACHE_SEC`, default 300) with mtime invalidation for module manifests, MCP config layers, `active_skills.json`, and probed package origins. A warm snapshot starts zero help-json or MCP server processes during prompt assembly. Every `call_job` still opens a short-lived stdio or streamable-HTTP session (SSE when `transport` is `sse` or the URL ends with `/sse`).
- **Providers**: `runner/providers/*.json` uses the same manifest shape as modules (`name`, `kind`, `verb`, `rests_on`). Package files are env-only (`LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`). Host URLs live in overlays — `<host>/providers` (~/.agents/providers by default) and `AGENTS_PROVIDERS_DIR` (agents-sandbox; strongest pick on name collision), not in this clone. Completions **stream**; `first_byte_sec` is prefill silence, `idle_sec` is a stall between tokens. Do not wall-clock-cap a generation. The loop calls `complete(messages, tools)`. Modules with `as_tool` become OpenAI functions (`mcp.memory.search` → `mcp_memory_search`). One tool round maps `tool_calls` onto Cordis `execute_job`; it does not import package internals. Machine picks: `AGENTS_MODULES_DIR` overlay plus optional `enabled.json`.
- **Identity**: alias (`telegram:5712`) ≠ user (`u_…`) ≠ session (`ses_…`). `--detached-session` uses a session for one turn and does not store it as the active session. A session id starting with `routine:` is detached without that flag. Resume threads from **traces** (`channel` + `user` + `project`); `<host>/users.json` (`~/.agents/users.json`, `AGENTS_USERS_FILE`) is alias bindings only. Human profile: `USER.md`. Crypto: `agents-keys` / `did:key`. Product name: **Klanker**.
- **Zero Heavy Dependencies**: Python standard library (`subprocess`, `json`, `datetime`, `pathlib`, `logging`, `urllib`) plus `agents-workspace` for the Host/Workspace path contract. No Celery, no Redis, no cron daemons. Optional extras: `mcp` (FastMCP server + client SDK), `traces` (agents-traces).
- **Durable Manifests (Koru Principle)**: Every scheduled flow is declared in `runner/schedules/*.json` with the verified verb it rests on, its cadence, and its expected exit semantics (`exit 0 = healthy`).
- **Strict Layering (Cordis Principle)**: The executor owns no state, no domain store, and no semantics. It never imports module internals; it strictly invokes verified CLIs and inspects exit codes.
- **Job kernel**: Catalog JSON is the alphabet (`ITerm` view of Kernel.lean). `python -m runner.kernel` checks, mixes, reduces. Atom β is Cordis `execute_job`. Combinators are norm/konst/comp/app. NL skill bodies are not terms.

## Commands
- Validate all manifests: `python -m runner.executor --validate`
- FastMCP: `python -m runner.mcp_server` (copy `mcp.json.example` into the host MCP config; do not auto-merge `~/.cursor/mcp.json`)
- List modules: `python -m runner.loop --list-modules`
- List advertised tools: `python -m runner.loop --list-tools`
- List completion providers: `python -m runner.loop --list-providers`
- Assemble one request (no HTTP): `python -m runner.loop --channel telegram --user 123 --message "hi" --assemble-only`
- Resume a thread: `python -m runner.loop --session ses_… --message "hi" --assemble-only`
- Detached turn: `python -m runner.loop --session ses_… --detached-session --message "hi" --assemble-only` (this turn uses that session; it does not become the active session)
- Complete via provider: `python -m runner.loop --user probe --message "hi" --complete --provider openai.default`
- Fast conversational turn without provider reasoning: `python -m runner.loop --user probe --message "hi" --complete --provider openai.default --reasoning off` (`low`/`medium`/`high` override explicitly; `HARNESS_REASONING` sets the default)
- Tool turn (no LLM): `python -m runner.loop --user probe --message canary --complete --provider scripted.tool --deliver buffered`
- Live LMS roundtrip: `python -m runner.loop --user probe --message "what is the sandbox canary" --complete --provider lmstudio.local` (host overlay; not in this clone)
- Delivery: HTTP always streams (hang detection). `--channel telegram` buffers the answer and prints `thinking...` on stderr. `--channel local` on a TTY writes tokens. `--deliver stream|buffered` overrides.
- Call a named module/schedule: `python -m runner.loop --call mcp.traces`
- Check a job term: `python -m runner.kernel --check runner/terms/skill-then-a2a.json`
- Reduce a job term: `python -m runner.kernel --reduce runner/terms/skill-then-a2a.json`
- Alphabet: `python -m runner.kernel --alphabet`
- Run all scheduled flows once: `python -m runner.executor --all`
- Tick due dynamic reminders: `python -m runner.schedule tick` (waits until claimed jobs finish) or in-process `runner.schedule.tick()`. `tick(wait=False)` returns after claiming so the caller is not blocked for the job timeout. A file lock makes overlapping ticks safe. A host cron or a platform scheduler, running as the same user as the service, can still call the CLI. An external tick does not inherit environment that only the long-running process sets (for example `AGENTS_APPROVAL_CMD`). This package does not start its own scheduler daemon.
- Approval gate (model `call_job` only): `AGENTS_APPROVAL_CMD` with `{user}` substitution, `AGENTS_APPROVAL_MODE=off|ask|strict`. Unset command = current behavior. Per-action rules (`approval.rules` in host `agents.json` or workspace `config.json`, or `AGENTS_APPROVAL_POLICY` / `AGENTS_APPROVAL_RULES`) layer on that tier. `deny` blocks, `ask` prompts when a command is set, `allow` does not skip a tier prompt. Action keys include `tool:<module>`, `cmd:<command>`, a command spec's `action` (for example `fs.delete`), and `git.push:<branch>`. `register_action_classifier` adds keys.
- Persona messaging: `persona.list` / `persona.inbox` (read-only) and `persona.ask` / `persona.handoff` (mutating) wrap `python -m runner.persona_tool`. Sender = `AGENTS_PERSONA` env; `AGENTS_PERSONA_HOP`/`AGENTS_PERSONA_MAX_HOPS` cap recursion (default 3); `AGENTS_PERSONA_SELF=1` allows self-messages. `ask` is a synchronous delegate turn; `handoff --wake` an async one.
- Git tool: catalog module `git`, verb `python -m runner.git_tool`. Default branch protected when git records it; force-push blocked; authors enforced only when configured (`AGENTS_GIT_PROTECTED`, `AGENTS_GIT_FORCE_PUSH`, `AGENTS_GIT_AUTHORS`, `AGENTS_GIT_AUTHOR_MODE`, or config key `git`).
- Pre-turn recall is off by default. `AGENTS_RECALL=1` or `recall.enabled` injects one instruction line and bounded hits from `register_recall_provider`, `AGENTS_RECALL_CMD`, and a repo scan (`AGENTS_RECALL_SOURCES`). `python -m runner.recall_eval` judges use-or-search against asking.
- Wall-clock injection: `AGENTS_CLOCK=0` suppresses every real-time surface — the `<clock>` message, the session `start_date` attribute in `<runtime_context>`, and `<ts>` stamps on replayed history — for frozen/replay worlds whose dates are not the host's.
- System-prompt frame override: `<ws>/prompts/system_prompt.txt` wins, then `AGENTS_PROMPT_TEMPLATE_FILE`, then inline `AGENTS_PROMPT_TEMPLATE`. Whole-section slots `{instructions}`, `{skill_catalog}`, `{runtime_context}` are spliced into the frame; unknown slots pass through. Empty means the built-in layout, which stays byte-identical.
- Pinned verbs: `AGENTS_PINNED_MAX_CHARS` (default 2500) sizes the pinned-block budget per deployment — type-faithful nested examples are not small, and clipping otherwise drops hot verbs. The block is toolset-scoped like every other prompt surface. Terminal rounds (`tools=None`) never coerce text-emitted tool markup: a coerced call cannot execute there, so coercion would silently eat the reply.
- Argument validation: `call_job` fails loud before approval/execution when a required key is missing or a key is invented — the error names the offending keys plus the valid parameter list, so a corrected retry lands in the same turn. The contract layer is the resolved command spec, never the router envelope: `commands_from` modules with no resolved command skip validation, `additionalProperties: true` schemas stay open, and the tolerant-mapped legacy modules (`mcp.terminal`, `mcp.memory.add/read`, `mcp.schedule.add`) keep their documented synonyms. Presence only, never types — nested shapes remain the tool's own contract. The `call_job` description carries the discovery contract: exact names from pinned examples or `load_schema`, invented or missing required parameters are rejected with the valid names.
- Failed-mutation repair gate (truthfulness invariant, default on): a turn may not end while a mutating call this turn failed and was neither repaired nor disclosed. When the model attempts to end such a turn, the harness names each unrepaired failure once — tool plus error — and forces one more completion with tools live: retry corrected or inform the user, never report success over a failed mutation. Repair detection is module-level and order-aware (only a later success of the same tool repairs); approval denials are exempt (already communicated with do-not-retry guidance); each distinct failure is noticed at most once so genuinely impossible ops are not nagged. `AGENTS_REPAIR_FAILED_MUTATIONS=0` disables, `AGENTS_REPAIR_MAX` (default 2) caps notices per turn. The wire contract is exit codes — a tool that prints errors to stdout with exit 0 is a broken tool, not a gate case.
- Text-emitted tool markup in content (`<tool_call>` with a JSON body or the `<function=name><parameter=k>` variant, including multi-call blocks) is coerced into real tool calls at the loop layer — endpoints without server-side tool parsing still execute the model's trained call format.
- Tool output cap: `AGENTS_TOOL_OUTPUT_MAX` (default 32768 characters) is the first page. Output over the cap keeps that prefix, then one `<page offset="..." next_offset="..." total="..." truncated="1" digest="..." sha256="..."/>` line that can make the shown string longer than the cap. `call_job` `read_content` continues it (`next` true, or `offset` = `next_offset`; `digest` optional for the latest page). Page size is `AGENTS_PAGE_CHARS` (default 32768), also `page_chars` in `<ws>/config.json` or `<host>/agents.json`. Hosts register `runner.register_content_backend` or set `AGENTS_CONTENT_READ_CMD`. No registration and no stored body: the tool says the content is unavailable. This path does not import agents-traces or agents-memory. Trace `stdout_tail` / `stderr_tail` stay 1000 characters; `execute_job` also returns the full `stdout` and `stderr`.
- Recent tool context: `AGENTS_HISTORY_TOOL_EVENTS` (default 12) and `AGENTS_HISTORY_TOOL_PREVIEW` (default 4096). Longer previews keep a page tag. A body that already has a page or ref tag keeps that tag.
- Search coverage: grep, glob, and search results get a harness `<search files_searched="..." truncated="0|1" matches="..."/>` line after the untrusted fence. The tool's own count and `truncated` flag win (including `truncated` on stderr). A finished search that omits the count is filled by a bounded workdir walk (`AGENTS_SEARCH_MAX_FILES`, default 50000; `AGENTS_SEARCH_CENSUS=0` skips the walk). Do not claim a path is absent unless `files_searched` is an integer and `truncated` is 0.
- Project context: when the workdir is a git repo, or contains one, `AGENTS.md` is added to the system prompt. `README` is the fallback when `AGENTS.md` is missing, and a short summary when both exist. `AGENTS_PROJECT_CONTEXT=0` turns it off. `AGENTS_PROJECT_CONTEXT_MAX` (default 24000) bounds the text.
- Pre-PR: `call_job` `repo.pre_pr` discovers test and build commands from `package.json` scripts, `pyproject.toml`, `Makefile` targets, and fenced commands in `AGENTS.md`. `run` true executes that discovered argv. No command is invented. `AGENTS_PRE_PR_TIMEOUT` (default 300 seconds) bounds each command.
- Receipts: a successful mutating call adds `agents_harness.tool_receipt.v1` (`tool`, `args_digest`, `success`, optional tool `receipt`) to the rest of the turn. CLI success is exit code 0. A non-zero exit, `TIMEOUT` / `FAILED` / `ERROR`, or a harness failure string is not a receipt. Tool stdout is not scanned for the word error. `runner.register_final_check(hook)` may flag the draft. Remaining findings are trailer `response_flags`. No default product heuristic.
- Help-json side effects: `side_effects`, then `mutates`, then `annotations.readOnlyHint`. Missing metadata is mutating. Names and argument text are not a class. Default approval mode stays `off`. `commands_from: "help-json"` loads `<verb> --help-json`. A command spec may nest `subcommands` (one level); `argv[1]` or an `action`/`subcommand` argument resolves it for classification, argv building, approval keys (`cmd:proc kill`), and pinned rendering.
- Persona memory: `persona.json` `memory: "private"` gives a persona its own store at `<ws>/personas/<id>/memory` (`AGENTS_MEMORY_DIR` and `AGENTS_MEMORY_PATH` set at loop start / delegate spawn); default `shared` uses workspace memory. Private personas get both the shared and their private `<memory_rules>` block in the system prefix.
- `cordis_expose`: suite packages emitting `cordis_expose: true` in `--help-json` auto-mount as `mcp.<pkg>` modules when no manifest exists (`AGENTS_CORDIS_PKGS` extends the probe list, `AGENTS_CORDIS_EXPOSE=0` disables). Toolset members support `<glob>:<group>` — `mcp.browser:read-only` admits only read commands; a command spec `groups` list overrides the implicit side-effect group.
- Package modules: `mcp.browser`, `mcp.calendar`, `mcp.traces` discover commands via `commands_from: "help-json"`. `expose_commands: [...]` synthesizes `<pkg>.<cmd>` module rows (`command_pin` argv head, command `parameters` surfaced) — hand-written manifests with the same name win.
- Pinned verbs: a module manifest with `"pin": true` renders its discovered commands as ready `call_job` examples in the system prompt (capped at 2500 characters, clipped with `[pinned block clipped]`). `AGENTS_PINNED_VERBS=0` disables the block. The built-in Cordis tools stay unchanged.
- Chat commands on traces: `--message "/undo"` covers the last turn with an empty `frame` (projection drops it, log keeps it); `"/retry"` covers everything after the last user message and re-completes it; `"/compress [N]"` appends a compaction frame over all but the newest N events (default 6).
- Toolsets: `toolsets` in `<ws>/config.json` or `<host>/agents.json` names groups of module-name globs (`{"web": ["mcp.web.*"]}`). `AGENTS_TOOLSET` / `runner.loop --toolset` picks one; config `toolset` is a string or `{"default": "…", "<channel>": "…"}` for per-channel picks. The active set restricts `list_catalog`, `load_schema`, `call_job`, and the prompt module list; `all`/`off` means unrestricted, an unknown set name fails closed.
- Skills: `<ws>/skills/*/SKILL.md` (`AGENTS_SKILLS_DIR`, extra dirs in `AGENTS_SKILLS_EXTRA`). Tools `skill.list` / `skill.load`. `skill.catalog` remains an alias of `skill.list`.
- Workspace lock & delegates: `AGENTS_WORKDIR` sets the working directory; `AGENTS_WORKDIR_LOCK=1` (deprecated alias `AGENTS_WORKSPACE_LOCK`) confines verb `cwd` to `allowed_roots(ws)` + `AGENTS_WORKDIR_ALLOW`. Delegates (`mcp.delegate`, `python -m runner.delegate`) store state in `<ws>/run/delegates` (`AGENTS_DELEGATES_DIR`), track active depth in `<ws>/run/delegate.depth`, spawn with `ws.env(..., role="turn")` + `delegate_env`, and set `AGENTS_WORKDIR_LOCK=1` when `--workdir` is given. Approval allowlists live on the host (`AGENTS_APPROVAL_ALLOWLIST`, never inside a workspace).
- Attachments: `python -m runner.loop --attach <path>` (repeatable). Images are vision parts when `AGENTS_VISION=1` or the provider manifest sets `vision` / `capabilities: ["vision"]`; otherwise the path is text.
- Run specific flow: `python -m runner.executor --run <name>`
- Run test suite: `python -m unittest discover tests`
